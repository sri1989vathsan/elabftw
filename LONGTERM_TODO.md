# Long-term backlog

Ideas and open questions that aren't scheduled yet. Not everything here will get built.

- **Embed jspreadsheet's editing UI directly inline in TinyMCE**, instead of opening it in a popup. Would mean each spreadsheet becomes a persistent live widget synced continuously with TinyMCE's undo/serialization, rather than only on popup-close. Real cost with multiple spreadsheets in one document; only worth it if there's a concrete reason to want inline editing (e.g. seeing/editing numbers without leaving the document flow).
- **Backfill membership for existing subprojects** to match their parent project (new subprojects already default to the parent's member list at creation — see `ProjectManagementBoard.svelte`). Open question: should backfilling ADD the parent's members to each subproject's current list, or REPLACE it outright?
- **Plain-table column/row resizing in the main text is still annoying**, even after the current fixes (`table_sizing_mode: 'fixed'`, `overflow-wrap`/`word-break` on cells — see `src/ts/tinymce.ts` and `src/scss/_tinymce.scss`). Root cause is architectural: HTML tables in a rich-text editor use relative, content-driven widths, not an independent Excel-style grid, and TinyMCE's own resize math has known inconsistencies on top of that. A `table-layout: fixed` attempt to force independent columns was tried and reverted — it broke row-height calculations during resize. Real fix likely requires either living with the limitation for plain tables, or steering people toward the jspreadsheet-based spreadsheet insert (which already has proper independent sizing) whenever precise table control matters, rather than further CSS patching.
